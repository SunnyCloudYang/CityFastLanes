# 铅笔城 · City Fast Lanes — 技术方案与开发计划

> 状态：原型已完成（提交 `7e4189f`），本文档描述现有实现，并规划后续迭代。
> 最后更新：2026-10-28

---

## 1. 项目概述

一款运行在浏览器里的**素描风格城市交通沙盒**。城市里的汽车和自行车由 AI 自动驾驶，玩家可以：

- **只观察**：俯瞰整座城市的车流、红绿灯和拥堵；
- **跟随**：选中任意一辆车，用俯瞰 / 追尾 / 第一人称视角跟着它；
- **接管**：把选中的车从 AI 手里接过来自己开，随时交还给 AI，交还后它会自己回到车道继续行驶。

### 设计目标

| 目标 | 说明 |
| --- | --- |
| 开箱即玩 | 打开网页即运行，无需登录、无需加载大资源，全部几何程序生成 |
| 观察本身有趣 | 不操作也能看：车流有起伏、路口有排队、桥是瓶颈 |
| AI 简单但可信 | 不追求交通工程级精度，但不能穿模、不能路口死锁、不能明显犯傻 |
| 手绘一致性 | 所有视角都是同一套"铅笔+彩铅"画风，而不是贴图拼凑 |
| 可扩展 | 地图、车种、AI 规则、渲染风格都能独立替换 |

### 非目标（当前阶段）

- 真实物理（轮胎模型、悬挂）——用运动学自行车模型即可；
- 联机多人；
- 真实城市 GIS 数据导入（后续可选，见路线图）。

## 2. 玩法设计

### 2.1 三种状态

```
观察 ──单击车辆──▶ 跟随 ──双击 / Enter──▶ 驾驶
  ▲                 │  ▲                   │
  └──Esc / 拖拽空白──┘  └────── Esc ─────────┘   （交还 AI，回到跟随）
```

- **观察**：俯瞰视角，可平移 / 缩放 / 旋转。WASD 在观察态下用于平移镜头。
- **跟随**：镜头锁定选中车辆；被跟随的车不会被系统回收或删除。
- **驾驶**：同一时间只允许一辆玩家车。若未选车直接按 Enter，会接管镜头中心最近的车。

### 2.2 视角

| 视角 | 相机 | 用途 |
| --- | --- | --- |
| 俯瞰 `top` | 正交相机，60° 俯角，可 45° 步进旋转 | 全局观察、选车 |
| 追尾 `chase` | 透视相机，指数平滑跟随，滚轮调距离 | 驾驶主视角 |
| 第一人称 `fp` | 透视相机，眼高随车型；自行车有轻微颠簸和压弯侧倾 | 沉浸感 |

`V` 在三者间循环；没有选中车辆时强制回到俯瞰。

### 2.3 车辆

| 车种 | 长×宽 (m) | 期望速度 | 特点 |
| --- | --- | --- | --- |
| 轿车 `car` | 4.3×1.8 | 15 m/s | 主力车流 |
| 厢式车 `van` | 6.0×2.1 | 12.5 m/s | 约 15%，加速慢，制造车流差异 |
| 自行车 `bike` | 1.8×0.6 | 5 m/s | 靠车道右侧骑行，与汽车在路段上互不阻挡，在路口共享冲突检测 |

每辆 AI 车有一个 0.85–1.1 的"驾驶员系数"，乘在期望速度上，让车流不那么整齐。

### 2.4 地图

地图由参数化生成器产生，同一个种子总是生成同一张图：

| 地图 | 特征 | 玩法看点 |
| --- | --- | --- |
| 方格市中心 | 7×7 规则方格 | 基准场景，信号灯协调 |
| 老城区 | 节点随机扰动、删掉 22% 内部道路、限速更低 | 不规则路口、绕行 |
| 河畔双桥 | 中间一条河，只有两座桥 | 瓶颈与排队 |

### 2.5 操作

| 操作 | 按键 |
| --- | --- |
| 选车 / 接管 / 交还 | 单击 / 双击或 Enter / Esc |
| 换车 / 切视角 | Tab / V |
| 驾驶 | WASD 或方向键，空格手刹 |
| 镜头 | 拖拽平移，滚轮缩放，Q/E 旋转 |
| 时间 | P 暂停，1/2/3 = ½× / 1× / 3× |
| 画风 | K 或面板开关素描渲染 |

HUD 面板可切换地图、实时调整汽车（0–160）与自行车（0–80）数量。

## 3. 技术选型

| 领域 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | TypeScript（strict） | 模拟逻辑复杂，类型约束收益大 |
| 渲染 | Three.js | 成熟、体积可控，足以支撑后处理管线 |
| 构建 | Vite | 开发快，`?raw` 直接导入 GLSL |
| 测试 | Vitest | 与 Vite 同源，可直接跑无头模拟 |
| 素描效果 | 自研全屏后处理着色器 | 需要同时用到深度、法线和颜色，现成库难以定制 |

没有引入物理引擎和 ECS 框架：车辆数在数百量级，用普通数组和类就够，依赖越少越容易调试。

## 4. 总体架构

### 4.1 分层

```mermaid
flowchart TD
  subgraph 数据层
    G[map/generators<br/>参数化生成] --> MD[MapDef<br/>节点/道路/装饰]
  end
  subgraph 模拟层（纯逻辑，可在 Node 中运行）
    MD --> RN[RoadNetwork<br/>车道图/连接线/冲突/信号]
    RN --> W[World<br/>车辆、AI、生成回收]
    W --> V[Vehicle<br/>运动学模型]
  end
  subgraph 表现层
    RN --> SB[SceneBuilder<br/>静态城市网格]
    W --> VR[VehicleRenderer<br/>车辆网格+插值]
    VR --> CR[CameraRig<br/>三种视角]
    CR --> SK[SketchRenderer<br/>素描后处理]
  end
  subgraph 交互层
    IN[Input] --> GM[main.ts Game]
    HUD[Hud] --> GM
  end
  GM --> W
  GM --> CR
```

**关键约束：模拟层不依赖 Three.js 和 DOM。** 这让单元测试可以在 Node 里直接跑几分钟的交通模拟，也为将来把模拟搬进 Web Worker 留了余地。

### 4.2 坐标约定

- 模拟在二维平面 `(x, y)` 上进行，单位米，速度单位 m/s。
- 渲染时映射为三维 `(x, 0, y)`，Y 轴向上。
- 朝向 `heading` 为弧度，0 指向 +x；正转向为右转。

### 4.3 主循环

```
requestAnimationFrame
 ├─ 读取输入 → 写入玩家车 input（或平移镜头）
 ├─ 固定步长模拟：acc += realDt × timeScale；每 1/60 s 调用一次 world.step()
 │    单帧最多 12 步，超出则丢弃积压，防止卡顿后"死亡螺旋"
 ├─ 渲染插值：alpha = acc / DT，在 prevPos 与 pos 之间插值车辆位姿
 ├─ 更新信号灯材质、相机
 └─ 素描渲染；HUD 状态每 0.15 s 刷新一次
```

固定步长保证 AI 行为与帧率无关、可复现；渲染插值保证高刷屏上画面流畅。

### 4.4 目录结构

```

  map/
    types.ts         MapDef 数据格式

    maps.ts          地图注册表

    Signals.ts       信号灯控制器

    ai/IDM.ts        智能驾驶员模型
  render/
    SceneBuilder.ts  路面、标线、建筑、树、水、信号灯
    VehicleRenderer.ts 车辆网格、插值、拾取、选中高亮
```

## 5. 模块设计

### 5.1 地图数据格式（`MapDef`）

```ts
interface MapDef {
  id: string; name: string; seed: number;
  nodes: { id; x; y }[];                    // 路口/端点
  roads: { id; from; to; speedLimit; bridge? }[]; // 双向各一车道
  decor: { type: 'block'|'building'|'park'|'water'; polygon; height? }[];
  bounds: { minX; minY; maxX; maxY };
}
```

`MapDef` 是纯数据，是生成器和其余系统之间唯一的契约。将来手绘地图、JSON 导入、编辑器都只需要产出 `MapDef`。

当前生成器 `generateGrid` 的参数：行列数、间距、节点扰动 `jitter`、删路比例 `removeRatio`（删除时保持连通）、公园概率、限速、河流（位置、宽度、哪几行有桥）。

### 5.2 路网构建（`RoadNetwork`）

把"节点 + 道路"转成车辆能直接跟随的**车道图**：

1. **路段车道**：每条道路生成正反两条车道，各向右偏移半个车道宽（3.5 m），两端各缩进 9 m 给路口留空间。
2. **路口连接线**：每个路口为"所有驶入车道 × 所有驶出车道"生成三次贝塞尔曲线，标记直行 / 左转 / 右转 / 掉头。掉头只在断头路允许。
3. **弯道限速**：按曲线最小曲率半径计算 `v = sqrt(2.5 m/s² × r)`，与上下游限速取小。
4. **冲突关系**：同一路口内，来自不同驶入车道、且路径间距小于 2.4 m 或汇入同一出口的连接线互为冲突。
5. **信号灯**：三岔及以上路口自动加信号。驶入方向按与参考方向的夹角分成两组（大致南北 / 东西），两组交替放行。
6. **路口多边形**：由各方向路面边缘点求凸包，用于渲染路口铺装。

### 5.3 信号灯（`SignalController`）

两相位定时控制：绿 14 s → 黄 3 s → 全红 1.5 s，然后换另一组，周期 37 s。每个路口按 ID 设置不同的初始相位偏移，避免全城同时变灯。

### 5.4 AI 驾驶（`World.driveAI`）

每辆 AI 车每步依次做：

1. **路线**：路线队列少于 4 段时，随机挑一个目标车道，用车道级 A*（以通行时间为代价）补齐。实际效果是车辆在城市里不停地漫游。
2. **期望速度**：取车道限速与个人期望速度的较小值；再往前看 2 段车道，按 `sqrt(v_lim² + 2·1.4·距离)` 提前为弯道减速。
3. **跟车（IDM）**：沿当前车道和后续最多 3 段车道寻找最近的前车（最远看 70 m）。路段上汽车和自行车互相忽略，因为自行车靠右骑；在连接线上，同一入口出发但转向不同的车，在入口 10 m 内也算前车，以防路口追尾。
4. **路口预约**：车头距停止线小于 `max(6 m, 2.5 s × 车速)` 时尝试预约下一条连接线，必须同时满足：
   - 自己是本车道最前面的同类车；
   - 信号允许（红灯不进；黄灯时若无法舒适停下则继续通过）；
   - 没有车持有与之冲突的连接线；
   - 出口车道有足够空位（已扣除其他已预约车辆所需的长度）。

   预约失败时，在停止线前插入一个虚拟静止障碍，IDM 会让车平稳停住。"出口有空位才进入"保证车不会停在路口中间堵死交叉方向。
5. **避让玩家**：玩家车不在车道图上，所以单独检测：如果玩家车处于本车前方 35 m、车宽范围内的通道里，就把它当作前车。
6. **转向（Pure Pursuit）**：在路线上取前视点，前视距离为 `clamp(0.9 s × 车速, 3.5 m, 12 m)`，按自行车模型几何算出转向角。
7. **积分与投影**：用运动学自行车模型更新位姿，再投影回车道得到弧长 `s`；到达车道末端时切换到路线上的下一段，并释放连接线预约。

**兜底**：AI 车静止超过 45 s 会被回收重生（玩家附近 40 m 内和被跟随的车除外），用于化解罕见的死锁。

### 5.5 玩家驾驶与碰撞

- **操控**：油门 / 刹车 / 倒车自动切换，松开时有滑行阻力（含空气阻力项），手刹最大减速 9 m/s²。转向幅度随速度衰减（`1 / (1 + v/10)`），高速时不至于一打就翻。
- **碰撞**：只对玩家车做 SAT 检测，对象是附近车辆和建筑多边形，用最小平移向量推开；迎面撞击时速度反向并衰减到 15%。AI 车之间不需要碰撞检测，由预约和跟车逻辑保证不重叠。
- **边界**：玩家车被限制在地图包围盒外扩 30 m 的范围内。

### 5.6 接管与交还

- **接管**：先释放其他玩家车，再把这辆车从车道图上摘下（清空车道、路线和预约），控制权改为 `player`。
- **交还**：在所有路段车道中，按"距离 + 6 × 朝向夹角"评分找最近的同向车道（夹角超过约 110° 的直接排除），吸附上去重新规划路线。车不会被瞬移，Pure Pursuit 会把它自然拉回车道。

### 5.7 渲染

**静态场景（`SceneBuilder`）**：路面、路口铺装、车道虚线、停止线、街区、程序生成的建筑（高度随机）、公园和树、河流、信号灯杆。整张地图在加载时一次性生成，切换地图时整体销毁。

**车辆（`VehicleRenderer`）**：用盒子、圆柱和球拼出低多边形车身，几何体和材质全局缓存。每帧按 `alpha` 插值位置和朝向，自行车按转向和车速侧倾。俯瞰时选中的车脚下有圆环标记，跟随为红色，驾驶为蓝色。拾取时用射线找最近的车，俯瞰视角下拾取容差随缩放放大。

**素描后处理（`SketchRenderer` + `sketch.frag`）**：

1. 场景渲染两遍：一遍输出颜色和深度，一遍用法线材质输出法线；
2. 全屏合成一遍完成：
   - **描边**：深度的拉普拉斯（正交相机用线性深度，透视相机用 1/z，使平面上恒为零）加上法线差，两者取大；
   - **排线**：按亮度分四档，叠加 45°、−45°、水平、垂直四组线，线条带噪声扰动和随机断口；
   - **彩铅**：饱和度高的表面（车、树、信号灯）保留颜色，以排线纹理调制；
   - **纸张**：纸色底、颗粒噪声、暗角；
   - **线条抖动**：时间按 1/8 s 量化，产生手绘动画特有的"线条沸腾"效果。

可以一键关闭，用来对比或在低端设备上降级。

### 5.8 UI（`Hud`）

纯 DOM 面板：地图选择、车辆数量滑条、时速按钮、暂停、素描开关、状态区（当前模式、视角、车辆数，以及选中车的类型、编号和时速）、快捷键帮助。

## 7. 已知限制

1. 每个方向只有一条车道，AI 不会变道和超车（自行车靠右除外）。
2. 左转不需要让对向直行。两相位信号下，两者被视为冲突，由预约机制保证先到先过，但不符合真实的让行规则。
3. 自行车与汽车在路口转弯时偶尔会有轻微视觉重叠。
4. 死锁靠"静止 45 s 后回收"兜底，而不是从规则上避免。
5. 排线固定在屏幕空间，镜头移动时有"纸贴在屏幕上"的感觉（shower-door 效应）。
6. 每辆车都是独立的 `Group`，绘制调用数随车辆数线性增长，200 辆以上需要实例化。
7. 只支持键盘鼠标，不支持触屏和手柄。
8. 只有方格类生成器，道路都是直线段。

## 8. 后续计划

按"先让模拟更可信，再让城市更丰富，最后加目标玩法"排序。每个里程碑都应能独立发布。

### M1 · 可玩原型 ✅ 已完成

车道级路网、信号灯、IDM 与 Pure Pursuit AI、路口预约、接管与交还、三视角、素描后处理、三张地图、无头模拟测试。

### M2 · 交通可信度

| 任务 | 方案要点 | 验收 |
| --- | --- | --- |
| 多车道道路 | `MapRoad` 增加 `lanes` 字段；`RoadNetwork` 生成并排车道，路口连接线按"左转用左侧车道、右转用右侧车道"分配 | 双向四车道地图能跑通现有测试 |
| 变道 | MOBIL 模型：变道收益 = 自身加速度增益 − 礼让系数 × 新后车的减速，超过阈值且安全才变；变道期间用横向偏移插值，而不是瞬移 | 慢车后方的车会超车；变道无穿模 |
| 左转让行 | 连接线上增加"让行"优先级：左转需要等对向直行清空，通过检查冲突连接线上的接近车辆 ETA 实现 | 不再出现左转车抢在直行车前面 |
| 保护左转相位 | 信号控制器支持多相位配置（N 相位 + 每相位允许的连接线集合） | 大路口可以配置 4 相位 |
| 自行车路口处理 | 自行车走独立的连接线（贴右侧），与汽车连接线单独计算冲突 | 测试加入"自行车与汽车重叠"计数 |
| 去掉回收兜底 | 统计死锁成因（多为环形等待），通过预约时检测出口链环路来避免 | 关闭回收后，120 s 测试无永久停滞 |

### M3 · 城市丰富度

| 任务 | 方案要点 |
| --- | --- |
| 曲线道路 | `MapRoad` 支持折线或样条控制点，`Lane` 本身已是折线，主要改造生成器和渲染 |
| 新生成器 | 环岛（单向环 + 让行入口）、放射状城市、有机生长路网（L-system 或张量场） |
| 单行道 | `MapRoad.oneway`，只生成一个方向的车道 |
| 行人与斑马线 | 行人沿人行道寻路；斑马线是一种特殊的冲突区，车辆预约时需检查是否有行人 |
| 地图 JSON 导入 / 导出 | `MapDef` 直接序列化；URL 带上生成器参数和种子，方便分享 |
| 简易地图编辑器 | 俯瞰视角下点击放节点、拖拽连道路，实时重建 `RoadNetwork` |
| （可选）OSM 导入 | 把 OpenStreetMap 的 way/node 转成 `MapDef`，用于真实街区 |

### M4 · 素描美术

| 任务 | 方案要点 |
| --- | --- |
| 世界空间排线 | 在物体材质里按世界坐标或三平面映射生成排线，后处理只负责描边，解决"纸贴屏幕"的问题 |
| 线宽随距离变化 | 描边采样半径按深度缩放，远处线条更细更淡 |

| 昼夜 | 夜间纸张变深色，车灯和路灯用加亮笔触表现 |
| 车辆细节 | 更多车种（公交、出租、摩托），公交有站点停靠行为 |
| 速度线与动势 | 高速时第一人称视角边缘加速度线，强化手绘动画感 |

### M5 · 玩法

| 任务 | 方案要点 |
| --- | --- |
| 目标模式 | 送货、接人、限时到达；路线提示用手绘箭头画在地上 |
| 交规评分 | 闯红灯、逆行、碰撞扣分；AI 车会按喇叭或闪灯（素描风格的气泡） |
| 观察者工具 | 热力图（拥堵）、车辆路线显示、信号灯配时调节，让"只观察"也能参与调参 |
| 回放 | 模拟可复现（固定种子 + 固定步长 + 输入记录），只需录制玩家输入就能回放 |
| 移动端 | 触屏虚拟摇杆、双指缩放，HUD 自适应 |
| 设置持久化 | 地图、车辆数、画风存入 `localStorage` |

### M6 · 性能与工程

| 任务 | 方案要点 | 目标 |
| --- | --- | --- |
| 实例化渲染 | 按车种和部件用 `InstancedMesh`，颜色走实例属性 | 500 辆车、桌面 60 fps |
| 空间索引 | 均匀网格哈希，用于玩家碰撞、AI 避让和交还时找最近车道 | `nearestLane` 从 O(全部车道) 降到 O(附近) |
| Web Worker 模拟 | 模拟层已不依赖 DOM，可直接搬进 Worker；用 `SharedArrayBuffer` 或每步传位姿数组 | 主线程只做渲染 |
| 性能面板 | 显示帧时间、模拟耗时、绘制调用数 | 方便回归 |
| CI 与部署 | GitHub Actions 跑 `npm test` 和 `npm run build`，部署到 GitHub Pages | 每次推送自动发布 |
| 视觉回归 | Playwright 固定种子截图对比 | 着色器改动可感知 |

### 建议的近期顺序

1. **M2：多车道和变道**。这是限制 1 的根本解决，也决定了后续路网数据结构，越晚改代价越大。
2. **M6：实例化渲染和空间索引**。多车道会让车辆数翻倍，需要提前把性能底子打好。
3. **M4：世界空间排线**。这是目前最明显的观感问题。
4. 其余按兴趣推进。

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 规则叠加后 AI 出现新死锁 | 保留"静止超时回收"作为最后防线；无头测试持续监控平均速度和停滞车数 |
| 后处理在低端 GPU / 移动端掉帧 | 素描开关已有；再加分辨率缩放（后处理在 0.5–0.75 倍分辨率下运行） |
| 多车道改造影响面大 | 先扩展 `MapDef`，默认单车道，保证旧地图和旧测试不变，再逐步启用 |
| 模拟与渲染耦合加深 | 坚持"模拟层不引用 Three.js"，代码评审时检查 `src/sim` 和 `src/map` 的导入 |
